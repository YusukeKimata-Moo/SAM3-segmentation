# SAM 3.1による画像のセグメンテーションとタイムラプス追跡

[English](README.md) | [日本語](README_ja.md)

Google ColabでSAM 3.1を使い、画像内の物体を切り出して、タイムラプスの各フレームで追跡するノートブックです。テキスト、対象物・背景の点、ボックスで物体を指定でき、複数の物体を扱えます。

結果は、白黒のマスク画像または元画像にマスクを重ねたオーバーレイ画像として保存できます。操作を再現するためのプロンプト情報も保存できます。物体の面積や移動速度などの測定は行いません。

## はじめに準備するもの

- **Google ColabのPython 3.12・GPUランタイム**：A100を推奨します。GPUにはネイティブBF16対応が必要で、このノートブックではT4は使えません。
- **SAM 3.1モデルへのアクセス権**：[Hugging Faceのモデルページ](https://huggingface.co/facebook/sam3.1)で利用条件に同意し、アクセスを申請してください。
- **Hugging Faceの読み取り用トークン**：セクション6で表示される非表示の入力欄に入力します。コードセルには直接書き込まないでください。
- **入力画像**：Google Driveに置くか、セクション3からアップロードします。

[SAM3_1_Segmentation.ipynb](SAM3_1_Segmentation.ipynb)をダウンロードし、Colabの **File > Upload notebook** から開きます。ノートブック以外のソースファイルをアップロードする必要はありません。

### Hugging Faceトークンの取得手順

1. [Hugging Face](https://huggingface.co/)でアカウントを作成し、ログインします。
2. [SAM 3.1のモデルページ](https://huggingface.co/facebook/sam3.1)で利用条件を確認し、アクセスを申請します。承認が必要な場合は、利用可能になるまで待ちます。
3. 同じアカウントで [Settings > Access Tokens](https://huggingface.co/settings/tokens) を開き、**New token** または **Create new token** を選びます。
4. 用途が分かる名前を付け、読み取り権限の **Read** を選んで作成します。このノートブックに書き込み権限は不要です。
5. 発行されたトークンをコピーして安全に保管し、ノートブックの**セクション6で表示される非表示の入力欄**へ貼り付けます。

**トークンを作成するだけではモデルのアクセス権は得られません。** モデルの利用が許可されたアカウントのトークンを使ってください。トークンをREADME、コード、スクリーンショットなどに載せないでください。詳しくは[公式のトークン説明](https://huggingface.co/docs/hub/security-tokens)を参照してください。

## 使える画像とフォルダの準備

対象は、**2次元の静止画像と2次元のタイムラプス画像**です。

| 形式 | 対応する画像 |
|---|---|
| TIFF・OME-TIFF | 8-bit／16-bitの単一チャンネルのグレースケール画像、またはRGB画像。単一画像、時系列スタック、フレーム別ファイルに対応 |
| JPG・JPEG | 8-bitのグレースケール画像またはRGB画像。1ファイルを1フレームとして扱う |
| PNG | 8-bitのグレースケール画像・RGB画像、または16-bitのグレースケール画像。1ファイルを1フレームとして扱う |

**RGB以外の複数チャンネル画像と、奥行き方向に複数の断面を持つ画像（Zスタック）は対象外**です。パレット画像、透過画像・RGBA、アニメーション画像、CMYK画像にも対応していません。

フレームごとに画像が分かれている場合は、1つの時系列を1つのフォルダにまとめてください。画像サイズ、グレースケール／RGBの区別、ビット深度は、すべてのファイルでそろえます。ファイル名は自然順で並ぶため、`frame2.png` は `frame10.png` より先になります。正解マスクや別の時系列の画像は混ぜないでください。

## 起動から画像の読み込みまで

ノートブックのセクション番号に沿って進めます。

| セクション | 操作 |
|---|---|
| **1：インストール** | セルを実行します。成功するとPythonセッションが自動で再起動するので、再接続後はセクション2へ進みます。再起動直後にセクション1を繰り返す必要はありません |
| **2：ツールの読み込み** | 再起動後に実行します |
| **3：画像への接続** | Google Driveをマウントするか、画像をアップロードします |
| **4：入力と処理範囲の指定** | 画像ファイルまたは画像フォルダのフルパスを `INPUT_PATH` に入力します |
| **5：モデル入力の確認** | 表示された画像の明るさ、フレームの順番を確認します |
| **6：モデルの読み込み** | 入力欄にHugging Faceの読み取り用トークンを入力します。読み込みには時間がかかる場合があります |
| **7：物体の指定と追跡** | 操作パネルで物体を指定し、追跡します |

### セクション4の主な設定

初めて使う画像では、短いフレーム範囲で動作を確認すると進めやすくなります。

| パラメーター | 入力する内容 |
|---|---|
| `INPUT_PATH` | 画像ファイル、または1つの時系列を入れたフォルダのフルパス |
| `AXES` | 通常は空欄。TIFFの次元情報を明示する必要がある場合のみ指定 |
| `SERIES` | TIFF内のシリーズ番号。JPG・PNGでは `0` |
| `START` | 最初に処理するフレーム。先頭は `0` |
| `STOP` | 処理を終了する位置。この番号のフレームは含めない。`None` なら末尾まで |
| `STEP` | フレーム間隔。`1` なら全フレーム、`2` なら1フレームおき |
| `INTENSITY_LOW`・`INTENSITY_HIGH` | モデル入力に使う明るさの下限・上限。通常は `None`。手動指定する場合は元画像の画素値を入力 |

例えば `START=0`、`STOP=20`、`STEP=1` では、先頭から20フレームを処理します。

JPG・PNGは、RGB画像も含めて `AXES` を空欄または `YX` にします。TIFFでは、グレースケールの静止画像は `YX`、時系列は `TYX` が代表的です。RGB TIFFでは色成分を表す `S` を使い、`YXS` や `TYXS` など、保存されている順序に合わせます。チャンネルや奥行き方向を、時系列の `T` として読み替えないでください。

元画像は変更しません。モデルには、時系列全体で共通の明るさの範囲を使って8-bit RGBに変換した画像を渡します。グレースケールでは一部のフレームから自動で範囲を推定し、RGBでは元のビット深度の全範囲を使います。セクション5の画像が暗すぎる、または白飛びしている場合は、セクション4の明るさの設定を調整し、セクション4以降を実行し直してください。

## セクション7：物体を指定する

**Frame** または **Frame number** で、物体を指定するフレームを選びます。パネル上のフレーム番号は、選択した処理範囲の先頭を `0` とした番号です。

### テキストでまとめて検出する

1. **Concept** に、`dog`、`person`、`car` などの短い英語を入力します。
2. **Apply concept / boxes** を押します。
3. マスクと物体IDを確認します。

同じ概念に当てはまる複数の物体を検出できます。検出のしやすさは、対象、背景、明るさ、物体の大きさなどによって変わります。

必要に応じて、テキストを適用する前に **+ Box** や **− Box** で長方形を描き、対象・対象外の見本を示せます。ボックスは、必ず1個の物体だけを選ぶ指定ではありません。

一度に使う概念は1つです。テキストや見本ボックスを変更したいときは、後述の手順で同じプロジェクト内から再検出できます。現在の結果も残したい場合は、先に保存してください。

### ボックスを見本にして、テキストなしで複数物体を検出する

**このノートブックでは、ボックスと点で役割が異なります。** ボックスは「このような物体を探してほしい」という見本です。囲んだ範囲だけに検出を限定する指定ではありません。

| 指定方法 | 役割 |
|---|---|
| **+ Box** → **Apply concept / boxes** | 対象物の見本を示す。ボックスの外も含め、画像全体から該当する物体をまとめて検出する |
| **− Box** → **Apply concept / boxes** | 対象外の物体の見本を示し、検出したい物体との区別を助ける |
| **+ Point／− Point** → **Apply points** | 特定の1物体を指定・補正する。似た物体全体へ自動で検出を広げる操作ではない |

ボックスだけで検出する場合は、次の順で操作します。

1. **セクション7を実行して、新しいプロジェクトを作ります。** 以前の結果を残したい場合は先に保存してください。
2. 代表的な物体が見えるフレームを選び、**Conceptを空欄**にします。
3. **+ Box** を選び、見本にする物体1個の全体が入るように長方形をドラッグします。
4. 必要なら、適用する前に別の物体にも **+ Box** を描きます。対象外の物体は **− Box** で囲みます。
5. **Apply concept / boxes** を押します。**Apply pointsではありません。** ボックスの外も含め、画像全体のマスクとIDを確認してください。
6. 必要に応じて、検出された各IDを選んで点で補正します。その後、**Directionを `both` にしてTrack** を実行します。

検出結果は見本や画像によって変わり、複数物体が得られるとは限りません。テキストとの併用もできますが、テキストとボックスでは同じ種類の物体を示してください。また、− Boxは対象外の見本であり、長方形の内部を単純に消去する操作ではありません。

### 適用済みの見本ボックスを追加・変更して再検出する

セクション7を実行し直したり、モデルを読み込み直したりせずに、同じプロジェクト内で再検出できます。適用済みの見本は、その参照フレーム上に破線のボックスで表示され、個数と参照フレームもパネルに表示されます。新しく描いてまだ適用していないものが「pending」のボックスです。

| Box update | 動作 |
|---|---|
| **Add to saved** | 適用済みの見本と、新しく描いたボックスを合わせて再検出する。同じ参照フレームで追加する |
| **Replace saved** | 適用済みの見本を破棄し、新しく描いたボックスだけで再検出する。見本の描き直し・削除や、参照フレームの変更に使う |

1. 前の解析も残したい場合は、先にプロンプトと結果を保存します。
2. **追加する場合**は、参照フレームに戻り、対象・対象外のボックスを描いて **Add to saved** を選びます。
3. **変更する場合**は、使いたい見本一式を描き直し、**Replace saved** を選びます。この場合は別のフレームを選んでも構いません。見本をすべて削除してテキストだけで再検出するには、pendingを空にし、Conceptにテキストを残してReplace savedを選びます。
4. **Apply concept / boxes** を押します。テキストも変更したい場合は、押す前にConceptを編集します。
5. 新しい物体とマスクを確認し、必要なら点で補正してから、再度 **Track** を実行してください。

**再検出すると、現在の検出結果は新しい結果に置き換わります。** 新しい物体には新しいIDと自動名を付けます。旧物体の個別名・除外指定・点補正は引き継がず、以前の追跡結果もクリアします。**Name prefixの共通名は保持**します。点だけで始めた解析から、テキスト・ボックス検出に切り替える場合も同じ扱いです。pendingのボックスを描いたり消したりするだけでは、再検出は行われません。

**Clear pendingやUndo pendingでは、適用済みの見本は削除できません。** 見本を削除するときはReplace savedを使ってください。また、異なるフレームの見本をAdd to savedで混ぜることはできません。検出候補が多い場合は、セクション6の `MAX_OBJECTS` による上限にも注意してください。

### 点で1個ずつ指定する

1. **Object** で **New object** を選びます。
2. **Tool** を **+ Point (target)** にし、対象物の内部をクリックします。
3. 除外したい周囲の領域があれば、**− Point (background)** に切り替えてクリックします。
4. **Apply points** を押し、マスクを確認します。
5. 別の物体を追加するときは、再び **New object** を選びます。

既存の物体を修正する場合は、**ObjectでそのIDを選んでから**点を追加し、**Apply points** を押します。テキストで検出した物体も同じ方法で補正できます。

**Undo pending** は未適用の点・ボックスを直前から1つ戻し、**Clear pending** は未適用の指定をすべて消します。すでに適用したプロンプトを取り消す操作ではありません。

### 名前を自動で付ける・まとめて変更する

物体ごとに名前を入力する必要はありません。テキストで検出した物体には、概念と物体IDを組み合わせて自動で名前を付けます。例えば `car` なら、`car 1`、`car 2`…となります。末尾の番号は物体IDで、名前ごとに振り直す連番ではありません。

点入力などで共通の名前を使いたい場合は、**Name prefix** に `target` などを入力してから物体を追加します。追加するたびに `target 1`、`target 2`…と名付けられ、**New object** を選び直しても共通名は保持されます。空欄の場合はConceptの文字列を使い、Conceptもなければ `Object` を使います。追跡中に新しく検出された物体にも、同じ命名規則を適用します。

登録済みの物体をまとめて変更するときは、共通名を入力して **Apply prefix to all** を押します。個別に名前を付けた物体も含め、除外されていない全物体を変更し、以降に追加する物体にもその共通名を使います。**New objectのままでも操作でき、セグメンテーションや追跡のやり直しは不要です。**

一部の物体だけ別名にしたい場合は、物体を選んで **Name** に名前を入力し、**Save name** を押します。名前は、パネルの画像と保存するオーバーレイに `1: car 1` のようにIDと併記されます。マスクの保存先も `masks/object_000001_car_1/` のようになり、JSONにも名前が残ります。`Object 1` などの名前のままなら、画像にはIDのみを表示し、フォルダ名も `object_000001` のままです。名前は検出・追跡の条件には使われません。

フォルダ名に使えない文字は保存時に置き換えますが、JSONには元の名前を保持します。各フレームのファイル名は連番のままで、複数物体を重ねたオーバーレイも `overlays/frame_000000.png` のように保存します。すでに出力したファイルは名前の変更だけでは更新されません。変更後の名前で残すには、別の空フォルダまたは新規フォルダへ出力してください。

日本語などの名前を画像に表示するには、その文字に対応したフォントが実行環境に必要です。利用可能なフォントから自動で選びますが、対応フォントがない文字は四角などで表示される場合があります。その場合は英数字の名前を使ってください。JSONと保存フォルダ名には、元の日本語名も保持できます。

### マスクを修正する・物体を追加する・除外する

以下の操作は、現在のプロジェクトでそのまま行えます。最初からやり直す場合を除き、セクション7を実行し直す必要はありません。テキストで検出した物体も、点で補正できます。

| やりたいこと | パネルでの操作 |
|---|---|
| マスクの出っ張りや、余分な背景領域を削りたい | 対象フレームに移動し、**Objectで既存IDを選択**。不要な領域に **− Point (background)** を置き、**Apply points** を押す |
| 物体の一部がマスクから欠けている | 対象フレームと既存IDを選び、欠けている領域の内部に **+ Point (target)** を置いて **Apply points** を押す |
| 別の物体を追加したい | 物体が見えるフレームで **New object** を選び、内部に **+ Point (target)** を1つ以上置いて **Apply points** を押す |
| 途中のフレームで追跡がずれた | そのフレームに移動し、修正する既存IDを選択。対象物・背景の点を追加して **Apply points** を押す |
| 不要な物体を解析から外したい | **Object** でそのIDを選び、**Exclude object** を押す |

**Apply pointsを押すと、そのフレームのマスクを再推論します。** 修正結果を確認したら、**Directionを `both` にしてTrackを実行**し、選択した時系列全体の結果を更新してください。修正・追加・除外を行うと以前の追跡結果は無効になるため、画像を出力する前に再追跡が必要です。

点の指定は、画素を直接塗ったり消したりする操作ではありません。背景点を追加すると、指定した場所だけでなくマスク全体が変わる場合があります。残したい領域に対象物の点を併用して調整してください。適用した点は物体・フレームごとに蓄積されます。**Undo pending・Clear pendingでは、適用済みの点は削除できません。**

**Exclude objectは、その物体を全フレームの解析・出力対象から外す操作**です。現在のフレームだけを非表示にする機能ではありません。除外を取り消すボタンはないため、元の状態を残したい場合は先にプロンプトと結果を保存してください。特定フレームの余分な領域だけを修正したい場合は、物体を除外せず、既存IDに点を追加して補正します。

時系列の途中で追加した物体を `both` で追跡すると、それ以前のフレームにも追跡を試みます。実際の出現前に誤ったマスクが付いていないか確認してください。また、これらの操作は保存済みの画像ファイルには反映されません。更新した結果は、別の空フォルダまたは新規フォルダへ出力してください。

### 見やすく表示する

**Display low**・**Display high** で表示の明るさ、**Mask opacity** でマスクの濃さを調整し、**Update display** を押します。拡大には **Zoom** を使い、画像領域内をスクロールして見たい場所へ移動します。

**パネルの明るさを変えても、モデルに渡す画像は変わりません。** セグメンテーションに使う明るさを変更するときは、セクション4の `INTENSITY_LOW`・`INTENSITY_HIGH` を設定し直してください。

## 全フレームへ追跡し、結果を確認する

開始フレームを選び、**Direction** を指定して **Track** を押します。

| Direction | 追跡する範囲 |
|---|---|
| `both` | 指定フレームから前後に追跡し、選択した処理範囲全体を扱う |
| `forward` | 指定フレームから末尾へ |
| `backward` | 指定フレームから先頭へ |

処理が終わったら、Frameを動かして各フレームのマスクとIDを確認します。うまく切り出せていないフレームでは点を追加して補正し、再度Trackを実行してください。**補正すると以前の追跡結果は無効になるため、画像を保存する前に追跡し直す必要があります。** 全範囲を出力する場合は `both` を使うと分かりやすくなります。

物体の接触、消失・再出現、分離・結合の前後では、IDが正しく対応しているかも確認してください。マスクが分かれたり結合したりしても、元の物体との対応関係が自動で記録されるわけではありません。

## 最初からやり直す・別の画像シーケンスへ切り替える

以下は、Colabのセッションが維持され、モデルを読み込み済みの場合の手順です。インストールやモデルの読み込みを繰り返す必要はありません。ランタイムがリセットされた場合は、セットアップの手順に沿って再開してください。

### 同じ画像で最初からやり直す場合

1. 残したいプロンプトはセクション8、追跡済みの結果画像はセクション9で保存します。
2. **セクション7を再実行**して、新しいプロジェクトを作ります。現在のプロンプトと追跡結果はセッションから消えますが、保存済みのファイルは残ります。
3. 新しく表示されたパネルだけを使い、フレームを選んでテキスト・点・ボックスで指定し直します。
4. 新しい結果を保存するときは、セクション8で別のJSONファイル名、セクション9で空または新規の出力フォルダを指定します。

この手順では、入力画像、処理するフレーム範囲、モデル入力の明るさの設定はそのままです。これらも変更する場合は、セクション4・5を実行してからセクション7へ進んでください。

### 新しい画像シーケンスに切り替える場合

1. 切り替える前に、現在のプロンプトをセクション8、追跡済みの結果画像をセクション9で保存します。
2. 新しい画像をアップロードする場合は、**セクション3**を実行して、その時系列の画像を選びます。すでにマウント済みのDriveに画像がある場合、この操作は不要です。
3. **セクション4**の `INPUT_PATH` を、新しい画像ファイルまたはフレーム画像のフォルダへ変更します。`AXES`、`SERIES`、`START`、`STOP`、`STEP`、明るさの設定も確認してから実行してください。前の画像に使った設定は自動では初期化されません。
4. **セクション5**を実行し、新しいモデル入力の見え方とフレーム順を確認します。
5. モデルとその設定を変えない場合は、**セクション6を飛ばしてセクション7を再実行**します。新しいパネルで物体を指定し、追跡してください。
6. セクション8では別のJSONファイル名、セクション9では空または新規の出力フォルダを指定します。同じ画像シーケンスの保存済み操作を再現する場合以外は、`REPLAY_PROJECT` を空欄にしてください。

前のシーケンスで保存したプロンプトを、異なる元画像に対して再現しないでください。`MAX_OBJECTS` などモデル側の設定も変更する場合は、セクション6を実行してからセクション7で新しいプロジェクトを作ります。

## セクション8：プロンプトを保存・再現する

このセクションでは、プロンプトや処理設定をJSONファイルに保存します。**マスクやオーバーレイ画像の保存は、次のセクション9で行います。**

### 保存するとき

`SAVE_PROJECT` に、**新しい `.json` ファイル名まで含めた保存先のフルパス**を入力します。`REPLAY_PROJECT` は空欄にしてセルを実行してください。両方が空欄の場合は保存も再現も行いません。既存ファイルへの上書きはできません。

### 保存した操作を再現するとき

同じ元画像と前処理設定を読み込み、セクション7で新しいプロジェクトを作ります。その後、`REPLAY_PROJECT` に**保存済みJSONファイルのフルパス**を入力し、`SAVE_PROJECT` を空欄にしてセクション8を実行します。

再現では保存した操作を計算し直すため、時間がかかる場合があります。マスクや物体IDが保存時と異なる場合は処理を停止します。JSONには画像そのものやモデルのメモリ状態は含まれないため、元画像も保管してください。

## セクション9：マスク・オーバーレイ画像を保存する

追跡と確認が終わったら、`OUTPUT_DIRECTORY` に**出力先フォルダのフルパス**を入力します。元画像フォルダの外に、空のフォルダまたはまだ存在しないフォルダを指定してください。存在しなければ自動で作成します。ファイルが入ったフォルダには保存できません。

`OUTPUT_MODE` で保存形式を選びます。

| 値 | 保存する画像 |
|---|---|
| `"mask"` | 背景が `0`、対象物が `255` の8-bit白黒TIFF。名前を付けた物体は `masks/object_<ID>_<名前>/`、初期名の物体はIDのみのフォルダへ保存 |
| `"overlay"` | 色付きマスク、ID、付けた名前を重ねたRGB PNG。`overlays/` へ保存 |
| `"both"` | マスクとオーバーレイの両方 |

画像サイズは元画像と同じで、フレームごとに別ファイルになります。マスクの画素値はIDではありません。**どの物体のマスクかはフォルダ名で区別**します。その物体が存在しないフレームは、全画素が `0` のマスクになります。

物体同士が重なる場合、個別の白黒マスクにはそれぞれの領域を保持します。オーバーレイでは、重なった画素に小さいIDの物体を表示します。

出力先には、プロンプトと再現設定を記録した `project.json` も保存されます。出力フレームと元画像のフレーム番号の対応は、JSONの `export.source_frame_indices` で確認できます。JSONは最後に書き込まれるため、途中で出力が止まった場合は、別の空フォルダを指定して再実行してください。

**保存先はGoogle Driveを推奨します。** `/content` 内だけに置いたファイルは、ランタイムの終了で失われることがあります。セッションを閉じる前にDriveへ保存するか、ダウンロードしてください。
